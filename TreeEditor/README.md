# Tree Editor

A tree editor with two views: a lazily loaded database tree and a local cache where you edit nodes before applying them to the database.

Code: [`backend`](backend) (ASP.NET Core, EF Core, PostgreSQL) and [`frontend`](frontend) (React, TypeScript, jotai, TanStack Query, MUI, Tailwind).

## Run

From this folder (`TreeEditor`):

```bash
docker compose up --build
```

Open http://localhost:5173. This starts PostgreSQL, the API (http://localhost:8080/swagger) and the UI. On startup, the API applies migrations and seeds sample data (5 levels: Catalog → Electronics → Computers → Laptops → ThinkPad). **Reset** restores the sample data.

## Database schema

One table, `tree_nodes`:

- `Id uuid PK`: generated by the client, so new nodes can be created in the cache.
- `ParentId uuid NULL`: self-referencing FK with `ON DELETE CASCADE`, indexed.
- `Value varchar(500)`
- `Version bigint`: optimistic concurrency token.

## Key decisions

- The API returns one tree level at a time, paged, so the whole tree is never loaded.
- `POST /api/tree/apply` runs all cached changes in one transaction. A stale version returns `409`.
- The database cascade deletes descendants that were never loaded. The client sends only the topmost deleted nodes.
- Each cached node stores its ancestor path, which DBTreeView already knows. Deleting a node marks its cached descendants as deleted even if the nodes between them aren't loaded.
- The cache is persisted to `localStorage` and only calls the API on Apply and Reset. Load uses data DBTreeView has already fetched.
